# Actionables coordination

- Do not use the global `actionables-workflow` for repositories that already have an issue tracker. Use the repository's existing tracker when task coordination is needed.
- For substantive planning, research, implementation, debugging, handoff, or validation, use the global `actionables-workflow` skill when the Actionables MCP tools are available.
- Feature and bug sessions should provide their top-level Actionable ID as `workItemId`. Never browse globally available Actionables or guess a work item when that ID is absent.
- Do not claim tasks for simple questions or unrelated work. If tracking is unavailable or no existing task matches, continue the user's work and report that Actionables was not updated.
